01
الهدف والنطاق الحالي
هذه الوثيقة تحوّل الـBrand Guidelines والـSEO الحالي ومتطلبات المنصة الجديدة إلى Brief تصميم واحد يمكن التنفيذ عليه في Figma أو مباشرة في الواجهة، بدون الدخول في تصميم قاعدة البيانات أو الـBackend في هذه المرحلة.
قرار نطاق مهم
المنصة الحالية في هذا التصميم تحتوي على أربع حالات وصول فقط: Guest، Buyer، Seller، Admin. لا يوجد دور Seller/Buyer مشترك في هذا الإصدار. الـBuyer والـSeller مساران منفصلان، وكل منهما يحتاج إلى KYB قبل تفعيل الوظائف التجارية.

• Guest: يتصفح المحتوى العام والـListings المسموح بعرضها، ولا يستطيع تنفيذ شراء أو بيع.
• Buyer: بعد التسجيل والتحقق ونجاح KYB يستطيع الشراء، متابعة الطلبات، المدفوعات، الفواتير والشحنات.
• Seller: بعد التسجيل والتحقق ونجاح KYB يستطيع إنشاء وإدارة Listings ومتابعة الطلبات التي تم شراؤها منه والتسويات والشحنات.
• Admin: يدير الموافقات، KYB، Listings، Orders، Payments/Finance، Shipments، المحتوى العام وإعدادات الموقع والهوية القابلة للتعديل.
• كل الواجهات يجب أن تدعم English / Arabic، وLTR / RTL، وLight / Dark، وDesktop / Tablet / Mobile.
الأساس الذي لا يتم تغييره
• الموقع Public يظل B2B Green Coffee Sourcing / Trading وليس متجر قهوة Retail.
• الهوية البصرية Hills Coffee كما هي: الألوان، الشعار، روح الصور، والتوجه التحريري Premium / Natural / Traceability-focused.
• الصفحات العامة تستمر في احترام الـSEO الحالي، بينما صفحات الحسابات والطلبات والـAdmin تبقى Private / App-oriented.

04
الشعار والصور والـVisual Language
استخدام الشعار والصور يجب أن يظل مطابقًا للـBrand Guidelines، مع اعتماد الشعار الرسمي المرفق وعدم إعادة رسمه أو تغيير نسبه.
الشعار
• النسخة Horizontal هي الأنسب للـHeader والـDashboard Sidebar عند وجود مساحة.
• الحد الأدنى المقترح وفق الدليل: Horizontal 150px، وStacked 100px عند الاستخدام الرقمي.
• احترام Clear Space وعدم ضغط أو Stretch أو Rotate أو تغيير العلاقة بين عناصر الشعار.
• على الأسطح الداكنة يستخدم Variant رسمي مناسب/Monochrome أو Secondary؛ لا يتم اختراع recolor يدوي.
Photography Direction
• الصور الأساسية: Origin، Harvest، Processing، Green Coffee، Warehouses، Quality inspection، Bags/Lots، logistics.
• الأسلوب: Documentary editorial، ضوء طبيعي، خامات حقيقية، premium وموثوق، بدون إحساس stock-photo مصطنع.
• تجنب صور الكافيه واللاتيه والبن المحمص كهوية رئيسية لأن المشروع B2B Green Coffee.
Graphic System
• استخدام pattern المستوحى من أيقونة Hills بشكل خفيف، وتدرج Forest-to-Burnt Orange في اللحظات التحريرية فقط.
• الأيقونات Line/Outline وبسمك ثابت، بلون Forest أو Cream على Dark surfaces، مع عدم خلط أكثر من أسلوب أيقونات.
05
قواعد الـDesign System والمكوّنات
يجب أن تكون الواجهة Product UI حقيقية وليست مجرد صفحات Marketing. كل Component يحتاج حالات واضحة ومتوافقة مع Light/Dark وRTL/LTR.
• Header / Public Navigation / Mobile Drawer / Language switcher / Theme toggle
• Dashboard Sidebar / Topbar / Breadcrumbs / Workspace switch context
• Buttons: Primary, Secondary, Outline, Text, Destructive, Icon Button
• Inputs, Select, Combobox, Search, Date picker, File upload, Phone field, Country field
• Cards: Listing card, KPI card, Order card, Shipment card, KYB card, Document card
• Tables + responsive card-list alternative على الموبايل
• Tabs, Filter chips, Sort, Pagination, Status badges
• Dialog, Drawer, Confirmation modal, Toast, Inline alert
• Timeline / Stepper للـKYB والـOrder والـShipment
• Skeleton, Empty state, Error state, Unauthorized, Suspended, Pending review
• Document preview/download row، Invoice card، Payment proof card
حالات إلزامية لكل Component
• Default • Hover • Focus-visible • Active • Selected • Disabled • Loading • Success • Error.
• Touch target لا يقل عن 44x44px للعناصر الأساسية، مع focus ring واضح.
• Motion خفيف يخدم hierarchy: 160-420ms، بدون إخفاء المحتوى أو تأخير action؛ ويحترم prefers-reduced-motion.

12
Order / Cart / Payment Experience
حتى قبل حسم القرار المالي النهائي، يجب تصميم جميع الحالات بحيث يمكن تبديل منطق التنفيذ بدون إعادة تصميم المنصة من الصفر.
Flow تصميمي أساسي
• 1. Buyer يضيف Listing إلى Cart أو يبدأ Buy مباشرة.
• 2. Order Review يعرض الكمية والسعر والوحدة وأي tax/fees معروضة وفق القرار النهائي.
• 3. Place Order ينشئ حالة Order واضحة؛ Proforma قد تكون automatic أو تحتاج approval وفق القرار النهائي.
• 4. Payment step يعرض تعليمات التحويل البنكي/طريقة الدفع المعتمدة مع reference واضح.
• 5. Buyer يرى Payment Pending، ويمكن عرض Upload Payment Proof إذا تم اعتماده.
• 6. بعد Confirm Payment تتحول الحالة إلى Paid ثم Fulfilment/Shipment.
• 7. إذا كان الطلب من Seller، يعرض Admin/Seller settlement summary منفصلًا عن Buyer total.

Responsive وRTL وAccessibility
التصميم لا يعتبر Desktop هو النسخة الأساسية الوحيدة. كل شاشة رئيسية تحتاج Desktop + Mobile، مع Tablet للـTables والـDashboards المعقدة.
• Desktop: Sidebar ثابت للـDashboards، tables كاملة، multi-column layouts.
• Tablet: Sidebar collapsible، filters في drawer، tables تتحول إلى horizontal-safe أو card-list حسب المحتوى.
• Mobile: Bottom/Drawer navigation حسب الدور، cards بدل الجداول الثقيلة، actions ثابتة عند الحاجة بدون حجب المحتوى.
• RTL: عكس اتجاه sidebar، breadcrumbs، icons directional، timelines، drawers، paddings؛ لكن الأرقام/العملات/IDs تبقى مقروءة بشكل صحيح.
• WCAG 2.2 AA target: contrast، keyboard، focus، labels، error messages، semantic status لا يعتمد على اللون وحده.
• Empty/Loading/Error/Unauthorized/Suspended/Offline retry states جزء من التصميم وليس مرحلة لاحقة.

17
Checklist قبل اعتبار التصميم مكتملًا
هذه القائمة هي Gate للتصميم قبل بدء الـBackend/Database work.
• ☐ كل صفحات Public الأساسية موجودة ومتوافقة مع هوية Hills والـSEO الحالي.
• ☐ Guest / Buyer / Seller / Admin flows منفصلة وواضحة، ولا يوجد Seller-Buyer hybrid role.
• ☐ Buyer وSeller لديهم KYB كامل مع جميع الحالات including More Info / Rejected / Suspended.
• ☐ Buyer لديه Cart، Checkout/Order Review، Orders، Payment/Invoices، Shipments، Settings.
• ☐ Seller لديه Listings CRUD، Sales Orders، Settlement/Payout view، Shipments، Settings.
• ☐ Admin يستطيع approve/review Buyer/Seller، إدارة Listings/Hills Listings، Orders، Finance، Shipments، Content وSite assets.
• ☐ كل شاشة رئيسية لها Light + Dark وEN + AR وDesktop + Mobile.
• ☐ RTL مصمم فعليًا وليس مجرد text-align right.
• ☐ كل tables المعقدة لها Mobile fallback واضح.
• ☐ Status system موحد للأوامر، KYB، Listings، Payments، Shipments.
• ☐ Loading / Empty / Error / Unauthorized / Suspended states موجودة.
• ☐ Brand logo usage صحيح، لا stretch/recolor، والألوان/الخطوط متوافقة مع الدليل.
• ☐ Typography responsive؛ لا يتم استخدام 177px fixed على الموبايل.
• ☐ Accessibility: contrast، focus، touch targets، labels، status not-color-only.
• ☐ Business decisions pending (VAT/Proforma/settlement/refunds/payout timing) موثقة كـdesign variants وليست assumptions مخفية.
